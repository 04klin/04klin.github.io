# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal site built with Astro 5 (static output, no UI framework integrations), served at https://04klin.github.io. It is one immersive page: a landscape backdrop and, in the middle of the window, a terminal app ("the shell") on a pretend desktop that opens with a login notice greeting the visitor and in which visitors browse the photos by logging in to a pretend NAS. There is no header, nav or footer.

## Commands

```sh
npm install          # install dependencies (npm is the only package manager; no yarn.lock)
npm run dev          # dev server on port 4321, on all interfaces, also reachable as lobsterlocal / lobstertail (server.host and server.allowedHosts in astro.config.mjs)
npm run build        # astro check (type + schema check), then static build into dist/
npm run preview      # serve the built dist/ locally
npx astro check      # type check only
npx prettier --write src   # format (prettier-plugin-astro handles .astro files)
```

`npm run dev` and `npm run build` first run `scripts/sync-resume.mjs`, which copies `../resume/resume.pdf` (a sibling repository on the author's machine) over `public/assets/resume.pdf` when it has changed. The copy still has to be committed to be deployed; in CI the sibling does not exist and the script does nothing.

There are no tests and no lint script. `npm run build` is the correctness check: it fails on type errors, on content that does not match its schema, and on missing imported images.

## Deployment

Every push to `main` triggers `.github/workflows/deploy.yml`, which runs the build with `withastro/action` and publishes to GitHub Pages. There is no staging step: a commit on `main` is a production deploy.

## Architecture

The site separates content, structure and styling so that each can change alone (a theme change should touch only the layout, components and CSS).

**Layout.** Every page wraps its content in `src/layouts/Layout.astro`, which owns the `<head>`, the fixed backdrop (`Backdrop.astro`, see **Backdrop** below), the boot screen and the `<main class="page">` column. The Settings app on the home page changes the scene. Props, all optional: `title` (tab title `"<title> | Kevin Lin"`; omitted on the home page), `description` (search and link-preview summary) and `walk`.

**Link previews.** The layout emits Open Graph and Twitter card tags so shared links unfurl (Discord, iMessage, LinkedIn). They need absolute URLs, built from `site` in `astro.config.mjs`. Every page shares one picture, `public/assets/og-image.png` (1200x630), rendered from `scripts/og-image.html` by `scripts/make-og-image.sh` (headless Firefox); edit the HTML and rerun the script rather than editing the PNG. The script copies the mountain landscape out of the built home page, so run `npm run build` first. `theme-color` is the accent green because Discord uses it for the embed's side bar. Platforms cache previews, so changes can take a while to show.

**404.** `src/pages/404.astro` builds `404.html`, which GitHub Pages serves for unknown paths. It is a short terminal: `cd <the path>`, `cd: no such file or directory`, and a `cd ~` link home.

**Pages and redirects.** The site is the home page (`index.astro`, which renders `Shell.astro`), the 404, and the switched-off projects page. The old `/photography` page is gone; `redirects` in `astro.config.mjs` sends it to `/`.

**Site settings.** `src/site.ts` exports `contact` (email, GitHub, resume path; listed in the shell's home folder), `shellHost` (the host name in every prompt, `kevinlin.sh`), `siteVersion` (arbitrary, shown on the boot screen) and `features`.

**Switched-off sections.** `features` in `src/site.ts` turns unfinished sections off without deleting them. `features.projects` is currently `false`: `/projects` builds as a redirect to `/`, and `projects/` is left out of the shell's home folder. Set it to `true` to bring them back (the projects page has no way back home other than the browser, so give it one when it returns).

**Boot screen.** `BootScreen.astro` is a shell-style intro shown over the first page of a visit for about three seconds, then it fades out; a click or key skips it. It prints `guest@<shellHost>:~$ ./hello`, the site version (`siteVersion`, arbitrary) and the Astro version, the visitor's own date and time, a few `[ ok ]` lines (including the scene, season and time of day they got), and a pixel loading bar driven by the registered integer `--pct`. Each line appears at its inline `--at` time. The layout's head script sets `data-boot` on `<html>` only on the first page of a visit (`sessionStorage`), with motion allowed and JS on; `src/scripts/boot.ts` removes it. The shell's `reboot` command sets `reboot` in `sessionStorage` and reloads, so the boot screen plays again (with reduced motion it just reloads: the boot screen is all animation). `shellHost` and `siteVersion` live in `src/site.ts`.

**The desktop (home page).** The home page is a small desktop (`Shell.astro`): the landscape is the wallpaper, app icons (Terminal, Photos, Settings) sit down the left (in a row along the top on phones, hidden without JavaScript), and each app runs in its own window (`Window.astro`: title bar with the three lights and a title). `src/scripts/windows.ts` is the window manager: icons (`[data-open-app]`) open apps, an app registers `start`/`end` hooks with `registerApp`, and window state is in attributes the stylesheet reads (`data-live` running, `data-open` showing, `data-active` in front and gets the keyboard, `data-zoomed`, `data-placed` with `--x`/`--y` once dragged, `data-sized` with `--w`/`--h` once resized). The red light closes a window and ends its app (opening it again starts fresh); the yellow light minimizes (the app carries on; the icon brings it back); the green light, or a double click on the title bar, fills the screen. Drag a title bar to move a window, or an edge or corner (the `[data-resize]` strips in `Window.astro`) to resize it from its default size, down to 320×180 (neither on phones, where every window fills the screen below the icons); a press anywhere in a window brings it to the front. Windows stay clear of the icon column. The terminal's glass is `--panel` with a 16px blur; Photos and Settings are solid (`--panel-solid`), and so is the terminal while another app is open, so one window never shows through another.

**The terminal.** It fills the screen less a margin and opens by itself after the boot screen. The page itself does not scroll; the text scrolls inside `.term-scroll`. `src/scripts/shell.ts` runs it: each session types `cat /etc/motd`, which prints the login notice (rules of `=` clipped to the terminal's width, "Hi, I'm Kevin." at the normal size as the page's `<h1>`, and two lines; edit it in Shell.astro), then `ls`, which lists the home folder (`photos/`, `resume.pdf`, `github.url`, `email.txt`). Every name has an icon (`FileIcon.astro`: a folder, or a file by extension; the shapes are CSS masks under `[data-icon]` in the stylesheet). Every name in the output can be clicked; a click types the matching command into the prompt and runs it (`linesFor` works out the command from where the visitor is), and visitors can also type commands (`help`, `ls`, `cd`, `open`, `cat`, `ssh nas`, `exit`, `clear`, `reboot`, a few jokes), with Tab completion (a second Tab lists the choices) and history (↑ ↓, Ctrl+R reverse search, `history`, `!!`, `!n`, `!-n`, `!text`; kept in `sessionStorage` for the visit, so it survives closing the window and `reboot`). Ctrl+D on an empty line runs `exit`; `cd -` goes back to where the last `cd` came from (across the nas login too), and `cd` takes absolute paths (`/home/guest`, `/volume1/photos/<album>`). Each session starts with a Mac-style `Last login: <time> on ttysNNN` line, the time of the visitor's previous session (`lastLogin` in `localStorage`, the only thing the site keeps between visits). Clicking `resume.pdf` runs `open resume.pdf`, which opens the PDF viewer; clicking `github.url` runs `cat` first rather than opening it, which prints the shortcut with its address as a link (without JavaScript both names link straight to their files). A typed `cat resume.pdf` prints the PDF header and an `open resume.pdf` link. `photos/` is a network share: `cd photos` logs in to the nas (a short login message) and `ls -l` lists the albums as folders (`ls photos` lists them without going in); `cd <album> && ls` shows its photos as thumbnails with their file names, and clicking one (or `open <file>`) opens it in the Photos app. Going into an album gives the backdrop that album's season (`showSeason` in `scene.ts`, not saved); `cd ..`, `exit` or closing the window brings the visitor's own season back. `exit` in the home folder closes the window. Work still running when a session ends (typing, a login) checks the session counter and stops.

**The Settings app.** `SettingsApp.astro` and `src/scripts/settings.ts`: radio groups for Appearance (theme), Season and Wallpaper (landscape), each with an Automatic (Random for the wallpaper) choice that clears the saved value. A change applies at once (`chooseScene(part, value | null)` in `scene.ts`; a theme or landscape change crossfades the whole page with a view transition, never a circle or wipe; a season change does not, see **Backdrop**), saved in `sessionStorage` for the visit. The landscape list is repeated in the component, because `scene.ts` only runs in the browser.

**The PDF viewer.** `ResumeApp.astro` and `src/scripts/resume.ts` (app name `resume`): a window with no desktop icon, opened only from the terminal (`open resume.pdf` or `open resume`, which work anywhere, the nas included, and also bring it back when minimized). It shows `contact.resume` in an `<iframe>` (the browser's own PDF viewer), loaded the first time the app opens, with nothing around it (the browser's viewer has its own download and print buttons). Where `navigator.pdfViewerEnabled` is false (most phones) it shows a note with links to open or download the file instead. Clicks inside the PDF never reach the page, so the window comes to the front when the iframe takes focus.

**The Photos app.** `PhotosApp.astro` and `src/scripts/photos.ts`: a gallery window with the albums down the side (a row on phones), the chosen album's photos as a grid, and a viewer for one photo over the album (← → step through it, Esc or the back button returns; the keys work while Photos is in front). Choosing an album changes the backdrop's season like the terminal does; closing Photos sends `photos:closed`, and the terminal puts back the season for where it is. The terminal opens photos with `openPhoto(dir, index)`. Without JavaScript Photos is not there; the terminal's `<noscript>` listing links every photo instead.

Shell.astro renders everything the scripts show, so images go through Astro: the notice and the home `ls` output (also what shows without JavaScript, together with a `<noscript>` listing of every album), `<template data-out="...">`s for the albums listing and each album, the Photos app's grids, and the album data (viewer URLs, seasons) as JSON in `data-shell` and `data-photos`. The script clones those; it never builds image markup. The terminal stays hidden until the script has rebuilt it (`data-js` is set on `<html>` by the head script). Without JS, links still work and every album is listed. With reduced motion, nothing is typed out; output shows at once.

**Content collections.** Projects are a YAML list in `src/content/projects.yaml`, with the schema in `src/content.config.ts`. Each entry needs a unique `id`, a `title`, an `order` number and its `tech`; it may have a `context` (where it came from, e.g. "Coursework"), an `about` (a sentence or two, written as a showcase rather than resume bullets; leave it out when there is little to say), `links`, and a `status` (shown as plain accent text, e.g. "In progress"); the page sorts by `order` because collection order is not guaranteed. To add a project, add an entry to the YAML file. `Project.astro` takes an entry's `data` as props, typed from the schema.

**Photos.** Photos live in `src/assets/photography/` at full camera resolution. The albums are listed in `src/photos.ts`: each has a `dir` (its folder name on the nas), a `date` (`"YYYY-MM"` or `"YYYY"`; its season comes from `seasonOf` in `src/scripts/seasons.ts`), `photos` (`file` name in that folder and `alt`), and an optional `link` to an external album (shown as `album.url`). Albums are sorted newest first automatically. To add photos, drop the files in the folder and name them in an album; files are found with `import.meta.glob`, and the build fails on a name that does not exist. Astro generates the WebP thumbnails (`<Image>`) and a 2400px version for the Photos viewer (`getImage`) at build time, so do not add hand-made thumbnails. `flickrUrl` and `camera` are there too. Icons, PDFs and the poster stay in `public/assets/` and are referenced by absolute path (`/assets/...`); those paths are not checked at build time.

**Styling.** One global stylesheet at `public/assets/styles.css`, hand-written (the old Webflow export is gone). Design tokens (colours, fonts, radius, page width) are custom properties on `:root` at the top; change the look there first. There are two themes: night (the `:root` defaults) and day (`:root[data-theme="day"]` overrides the colour tokens). Any new colour that should differ between them must be a token or get a day override. Components and pages carry no scoped styles; they use the global classes (`term`, `ls`, `tiles`, ...). Fonts (IBM Plex Sans and IBM Plex Mono) are loaded from Google Fonts in the layout's `<head>`.

**Backdrop.** `Backdrop.astro` holds four landscapes (mountains, river valley, lake, rolling hills), all in the page, each drawn at build time from its own fixed seed so it never changes between builds. Three attributes on `<html>` decide what shows, set by the inline script in the layout's `<head>` before the first paint and again on `astro:after-swap` (a view transition swap replaces the `<html>` attributes):

- `data-scene`: the landscape, picked at random on every page load (kept in memory as `window.__scene`, so it stays the same across view transition navigations), unless one was chosen in Settings during the visit (`sessionStorage` `scene`). No button. Without JS, mountains.
- `data-season`: follows the date (northern hemisphere).
- `data-theme`: `day` from 7am to 7pm on the visitor's own clock, `night` otherwise.

A choice made in the Settings app lasts for the visit only (`sessionStorage`), so the next visit follows the calendar and clock again (`chooseScene` in `src/scripts/scene.ts`). Each landscape is drawn in depth layers (`.layer-back`, `-far`, `-mid`, `-near`): a faint range behind the main one (`--back`), fog pooling at the foot of each layer (`#fog`, coloured `--haze`), shaded left faces on peaks and left halves of trees (away from the sun and moon on the right; `--shade-color`, `--shade-strength`), and the nearest ground darkening towards the bottom (`#near-shade`). The back layers use their own seeds, so the older shapes stay the same. For realism the detail is generated too, each from its own seed so the composition (where peaks and trees stand) stays put: ridgelines and creases are roughened by midpoint displacement (`jag`), snow caps follow the rock and reach down the gullies, faint gullies (`.gully`) furrow the lit faces, wooded ridges get a treeline edge (`treeline`), pines are tiers of drooping boughs on a trunk and broadleaf trees clumps of round crowns. Fog stays thick below each layer's foot (`fogBelow`), so it never ends in a hard line, and a fixed noise image over the whole backdrop (`.backdrop::after`) adds a fine grain. The detail is most of the home page's weight (about 78 kB gzipped), so keep an eye on it when adding more. The layers stay still: there is deliberately no parallax on the pointer (it caused motion sickness). The lake's reflection copies sit in the same layers as what they reflect. In the stylesheet, each season sets its daytime colours (`--far-day`, `--leaf-day`, ...); night colours are mixed from those with `color-mix`. Pines stay green all year; the round trees, ground, water and snow caps follow the season. A change of season (an album, or Settings) is not a view transition: the season colours are registered `<color>` properties that the stylesheet transitions over `--season-fade`, the snow caps and weather fade, and the page stays live. A page-wide view transition freezes the page into a snapshot and swallows clicks, which made clicking through albums lag (they alternate seasons). Falling petals, leaves and snow only run when motion is allowed; fireflies only on summer nights. Those live in their own layer, `.weather`, after the backdrop in `Backdrop.astro`: fixed above the page (it takes no clicks), so they drift in front of the terminal too. Nothing else moves in the scene: a train ride between landscapes and birds in the sky were both tried and dropped.

**The walk (time of day on scroll).** On pages whose layout gets `walk` (only the home page), scrolling down the terminal passes the time: by day from morning to golden hour, by night from dusk to the blue before dawn. Text colours never change; only the sky, land, sun or moon, stars and horizon glow do. It works through registered custom properties at the top of the backdrop styles (`--warm`, `--eve`, `--lift`, `--horizon`, `--stars`, `--orb-x`, `--orb-y`), whose initial values are midday and midnight, so every other page looks as it did before. The `walk-orb`, `walk-day` and `walk-night` keyframes animate them; the animation is paused and positioned from `--walk`, which `setupWalk` in `scene.ts` sets from the scroll of the element marked `data-walk-scroller` (the terminal), or of the page if there is none. Not a CSS scroll timeline, because one is inactive while there is nothing to scroll yet, which would show midday instead of morning. With reduced motion there is no walk.

**Motion and plain style.** The only moving things are the backdrop (clouds, mist, falling petals, leaves and snow, fireflies), the crossfade when the theme or landscape changes, the glide when the season does, a photo fading in in the Photos viewer, the boot screen, and typing in the shell (the intro's commands and those a click runs). The site deliberately has no scroll-reveal fades, cursor glow or tilt, gradient text, scrolling marquees, card grids, pill buttons or tech chips; typing appears only where a terminal would type. Links are plain underlined text. All animation CSS sits in the `prefers-reduced-motion: no-preference` block at the end of the stylesheet.

**Client scripts and view transitions.** `<ClientRouter />` is enabled, so navigation swaps the DOM without a full reload and module scripts run only once. Any script that attaches listeners to page elements must do so inside an `astro:page-load` listener, as the shell does (`setupShell`, which also removes its document listeners on `astro:before-swap`). The backdrop uses `transition:persist` so its animation continues across pages.
